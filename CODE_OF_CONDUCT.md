# Code of conduct

This project is small, so this is short.

Be decent to people. Assume the person you are replying to is acting in
good faith and knows things you do not. Criticise the code, the design or
the argument, never the person making it.

Concretely, things that are not welcome here: personal attacks,
harassment of any kind, demeaning or exclusionary remarks, publishing
someone's private information, and sustained disruption of a discussion.
Whether a joke was meant kindly is not the test. The test is the effect
it had.

Things that are welcome and worth saying out loud: asking a question you
think is obvious, saying you do not understand something, changing your
mind partway through a thread, and pointing out that a maintainer got it
wrong. This project's own documentation has been corrected several times
by someone noticing a claim did not hold. That is the good case, not an
awkward one.

## If something goes wrong

Raise it with the maintainer through
[GitHub](https://github.com/burinc). If a public thread has gone bad, say
so in the thread or privately, whichever you would rather.

There is one maintainer, so there is no committee and no appeals process.
What you can expect is that a report gets read and answered, and that the
outcome is explained rather than just applied. Responses run from asking
someone to edit a comment, through a warning, to blocking an account from
the repository.

If the person behaving badly is the maintainer, say so plainly in the
issue or pull request. A public record is the only real check that exists
on a one-person project, and it is a fair one to use.
